# 系统设计

## 输入与游戏分工

手机通过 Safari 打开手柄网页。屏幕方向参与体感角度计算，横屏时将重力投影到当前屏幕平面；握持中位可以重新校准，得到左右转向值。按键使用独立触点，油门与道具可以同时按住。

手机以约每秒 60 次的频率发送最新转向、按键和计数状态。电脑上的 Node.js 服务通过原生 WebSocket 转发，不使用 Socket.IO。服务不计算赛车物理或生成游戏画面。电脑浏览器接管输入后，执行车辆、漂移、竞赛、道具和对手逻辑，使用 Three.js 绘制画面，使用 Web Audio 播放声音。

## 连接

电脑浏览器通过本机 HTTP 打开游戏；手机使用 HTTPS 获取手柄页面，通过 WSS 发送输入。iPhone 的体感需要安全页面、运动授权及真实点击，因此本地运行器生成本机专用证书，并提供首次安装说明。

游戏在本机请求配对房间，电脑与手机使用不同的随机配对凭据。手机配对凭据位于二维码链接的片段内；网页读取后用于连接。服务验证角色、凭据、来源、数据格式和递增序号，只接受一个活动手机。配对信息仅保存在运行进程内，不写入仓库。

连接层通过消息往返估计耗时。实测耗时取决于无线网络、设备与浏览器，不承诺固定延迟。服务在超过 600 毫秒没有收到有效输入时通知电脑；游戏释放按钮并处理暂停与恢复，避免旧输入持续生效。

## 声音

菜单、比赛、最后一圈的原曲提前离线合成为完整循环音轨。运行时播放固定的循环节点，切换场景时交叉淡入淡出，避免繁忙画面让短时间音乐排程断供。

音乐不占用短音效的临时播放名额。引擎和持续声音按声音时钟更新，避免声音时钟暂停时不断堆积参数；降低对手引擎与实时混响的计算负担。只有声音环境真正关闭时才重建，短暂停顿恢复已有声音，同时保留用户主动静音的选择。

## 资源与部署

`npm run build` 将电脑网页与资源生成到 `dist/`。本地服务从 `dist/` 读取游戏，从 `phone/` 读取手柄。标题和循环音乐随项目保存，车辆、赛道等仍主要由代码生成。

项目可存放在普通电脑文件夹或其他存储位置，运行不依赖某个移动硬盘。证书在运行电脑上生成，不与源码打包分享。当前实现为本地单电脑游戏与手机手柄，不包含云端大厅或互联网多人赛车。
